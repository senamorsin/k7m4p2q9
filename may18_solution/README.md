# Прогноз выработки ВЭС

Репозиторий содержит воспроизводимый комплект для формирования прогноза почасовой выработки на 18.05.2026.
Публичный GitHub содержит все файлы комплекта, кроме директории `data/` с использованными обучающими и погодными данными. Полный ZIP-комплект для платформы дополнительно содержит `data/`.

## Состав полного ZIP-комплекта

- `submissions/submission_may18_current.csv` — текущий прогноз на 18.05.2026 с заголовком `Выработка`.
- `submissions/submission_may18_current_no_header.csv` — тот же прогноз без заголовка.
- `model_sources/model1.py`, `model_sources/model2.py` — исходный код двух независимых моделей.
- `model_weights/model1`, `model_weights/model2` — сохраненные веса.
- `data/raw/train_dataset_plus_may18_recent.csv` — обучающие данные.
- `data/raw/may18_features.csv` — исходные признаки для 18.05.
- `data/raw/may18_features_actualized_bestmatch.csv` — признаки 18.05 после актуализации прошедших часов погодой Open-Meteo.
- `run_ensemble.py` — нейтральная точка запуска ансамбля.

В публичном GitHub отсутствует только `data/`; остальные перечисленные файлы, включая веса и готовые CSV, опубликованы.

## Учет ремонтных работ 18.05

По сообщению организаторов, с 09:00 18.05.2026 на электростанции начались плановые ремонтные работы, ограничивающие выработку. Поэтому при оценке прогноза за 18.05 учитываются только часы `00:00-08:00` включительно. Финальный CSV все равно содержит 24 строки, но модельный выбор оптимизирован именно под первые 9 часов.

## Метод

Финальный прогноз на 18.05 строится двумя моделями:

- `model1`: физико-эмпирическая базовая кривая мощности, residual tree ensemble, табличные поправки по режимам ветра и аналоговая компонента.
- `model2`: компактный ансамбль градиентных деревьев по инженерным признакам ветра, времени, направления и плотности воздуха.

На свежих holdout-днях `2026-05-10`...`2026-05-17` для окна `00:00-08:00` лучше всего показала себя `model1` отдельно: средний MAE `5.126` МВт против `5.329` МВт у среднего `model1/model2`. Поэтому default-режим `run_ensemble.py` использует `model1` на часах `00:00-08:00`, а для часов `09:00-23:00` оставляет среднее двух моделей только для полноты 24-строчного файла. Обе модели используют фиксированные seed, CPU-only режим и клипирование результата в диапазон `[0, 90.09]`.

## Технические детали

`model1` сначала строит устойчивую базовую оценку через кривую мощности с поправкой на доступное число ВЭУ, плотность воздуха и режим ветра. Затем обучается ансамбль моделей остатка: градиентные деревья под MAE/median-логику, робастные таблицы поправок по направлению/скорости/часу и аналоговая компонента по ближайшим историческим погодным состояниям. Эта модель лучше удерживает физические ограничения и резкие режимы около cut-in/ramp.

`model2` проще и служит независимой проверкой: он использует инженерные признаки из исходной таблицы, включая sin/cos направления ветра, квадраты и логарифмы скоростей, вертикальный shear, gust ratio, proxy плотности воздуха, сезонные и суточные циклические признаки. Несколько деревьев с фиксированными seed объединяются медианой.

Финальный `run_ensemble.py` не переобучает модели, а только загружает веса, получает `parts/model1.csv` и `parts/model2.csv`, применяет правило scored-window и валидирует формат. Это сделано специально: итоговый запуск поздно вечером 18.05 должен быть быстрым, детерминированным и не зависеть от случайного переобучения.

## Воспроизводимость

- Используется Python-зависимости из `requirements.txt`; основной запуск проверялся через виртуальное окружение проекта.
- Все seed и число потоков зафиксированы в коде моделей.
- Веса `model_weights/model1` и `model_weights/model2` входят в комплект.
- Контрольный SHA256 текущего файла `submissions/submission_may18_current.csv`: `a8927e98470c37c59216f07bf29df54e948303302b7b3e10e4f66ab71ea2fbd6`.
- Проверенный размер итогового файла на 18.05: 24 строки, один столбец `Выработка`, значения конечны и лежат в `[0, 90.09]`.

## Запуск текущего прогноза 18.05

```bash
python run_ensemble.py \
  --features data/raw/may18_features_actualized_bestmatch.csv \
  --output submissions/submission_may18_current.csv \
  --no-header-output submissions/submission_may18_current_no_header.csv
```

## Обновление погоды перед дедлайном

```bash
python fetch_openmeteo_forecast.py \
  --target-date 2026-05-18 \
  --output-dir data/weather/openmeteo_forecast_2026-05-18 \
  --min-successful-sources 5 \
  --keep-going

python weather_consensus.py \
  --features data/raw/may18_features.csv \
  --weather-dir data/weather/openmeteo_forecast_2026-05-18 \
  --output data/raw/may18_features_actualized_bestmatch.csv \
  --target-date 2026-05-18 \
  --min-sources 1 \
  --sources best_match

python run_ensemble.py
```

Ближе к 23:00 МСК актуализация использует больше фактических часов за 18.05, поэтому прогноз должен стать надежнее.
